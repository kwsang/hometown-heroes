# 🇺🇸 Hometown Heroes: The Hometown Success Engine

### 🌟 Inspiration
The United States is not a monolith, but a vibrant mosaic of regional excellence. **Hometown Heroes** explores how the diverse American landscape—from its varied climates to its unique terrains—inspires and fosters the collective power of Team USA. By mapping the geographic foundations of success, I demonstrate that the path to the **LA28 Olympic and Paralympic Games** begins in backyards across the country.

## 🚀 What it does
**Hometown Heroes** is an interactive discovery engine that maps the geographic and climatic foundations of Team USA excellence. It transforms raw athlete data into a high-performance visual dashboard where fans can explore the "Success Hubs" that forge world-class talent.

*   **Interactive Success Map:** A sub-second, real-time map that allows fans to explore regional hubs, filter by sport, and discover where Team USA's strength is concentrated.
*   **AI-Powered Regional Narratives:** Using **Gemini 2.5 Pro**, the platform generates unique, compliant narratives for every hub, correlating local environment with athletic success.
*   **Custom Generative Visuals:** Every hub and sport features custom, optimized clipart generated by **Imagen 3.0**, giving each community a unique visual identity.
*   **Dynamic Highlighting:** An idle-state discovery mode that automatically features statistically significant hubs and floating sport bubbles.
*   **Community Cheer Meter:** Real-time fan engagement using Firestore atomic increments to support local hubs.

### 🏗️ How I Built It
I built a high-performance bridge between raw data and fan engagement using a robust Google Cloud pipeline. First, I used **Gemini 2.5 Flash Lite** to extract structured data from PDFs, which was then enriched with geographic context via **Google Maps APIs**. My architecture utilizes **BigQuery** for heavy analysis and **Cloud Firestore** as a low-latency serving layer for an instant UI experience. I leveraged **Gemini 2.5 Pro** and **Imagen 3.0** to generate compliant narratives and optimized community visuals. Finally, the system was deployed on **Google Cloud Run** to ensure a secure and scalable environment.

### 🏆 Accomplishments that I'm proud of
*   **High-Performance Architecture:** Successfully engineered a multi-tiered data flow using BigQuery, Firestore, and GCS, reducing frontend latency to sub-100ms.
*   **Advanced Multimodal ETL:** Built a self-healing pipeline that uses Gemini 2.5 Flash Lite to extract structured data from complex PDF layouts.
*   **Intelligent Asset Optimization:** Implemented an automated imagery pipeline that generates assets via Imagen 3.0 and optimizes them into WebP format, reducing payloads by over 80%.
*   **Self-Healing Asset Integrity:** Engineered an idempotent pipeline that cross-references BigQuery metadata with physical Cloud Storage blobs to maintain perfect synchronization.
*   **Quota-Aware Backoff Orchestration:** Implemented a sophisticated throttling layer for Vertex AI that respects strict 10 RPM quotas while maximizing throughput.

### 🧠 What I Learned
*   **Serving Layer Separation:** Moving real-time "reads" from BigQuery to **Cloud Firestore** transformed the user experience from "loading..." to "instant." 
*   **AI Collaboration & Critical Vetting:** Learned that AI-driven suggestions require rigorous architectural vetting; initial patterns using BigQuery for assets proved unscalable for serving.
*   **Structured Output Engineering:** I learned how to strictly enforce JSON schemas and boundary validation to ensure 100% data integrity when working with LLMs.

### 🚧 Challenges Faced
*   **Distributed State Synchronization:** Orchestrating data across BigQuery, Firestore, and GCS while ensuring recurring ETL cycles didn't overwrite existing AI-generated assets.
*   **Syntax Friction in Meta-Programming:** Managing the complexity of generating dynamic JavaScript via Python f-strings, requiring intricate escaping for template literals.
*   **Terminology Strictness:** Ensuring the AI never used "past" or "former" for Olympians and correctly identified upcoming Games like **LA28** and **Milano Cortina 2026**.

### 🧪 Reproducible Testing & Setup Guide

To verify the architecture and interactive UI locally, follow these steps:

#### 1. Local Environment Setup
Ensure you have Python 3.11+ and the Google Cloud SDK installed.
```bash
pip install -r requirements.txt
pip install -r scripts/requirements.txt
```

#### 2. Authentication & Configuration
Authenticate with Google Cloud and set the required environment variables.
```bash
gcloud auth application-default login

export GOOGLE_CLOUD_PROJECT="your-project-id"
export GOOGLE_MAPS_API_KEY="your-maps-api-key"
export API_KEY="your-app-secret-key"
```

#### 3. Data Pipeline Execution (The "Heal" Sequence)
The serving layer must be populated for the map to function. This multi-stage ETL process transforms raw PDFs into a high-performance system. Run these scripts in order:

1.  **Generate Sport Map:** `python scripts/generate_sport_map.py`
    *   **Purpose:** Initial extraction phase. Analyzes source PDFs to identify page ranges per sport and extract athlete boundaries for validation.
    *   **Gemini Calls:** One call to `gemini-2.5-flash` per PDF file in `resources/`.
    *   **Output:** `resources/sport_map.json`

2.  **Split PDFs into Sport Segments:** `python scripts/split_pdfs.py`
    *   **Purpose:** Re-chunks large sport sections into smaller segments (3-5 pages) to prevent model context truncation.
    *   **Gemini Calls:** None.
    *   **Output:** Multiple `.pdf` files in `resources/pages/`.

3.  **Parse Athlete Data from PDF Segments:** `python scripts/parse_athlete_pdf.py`
    *   **Purpose:** Iterates through segments to extract athlete names and participation years into structured JSON. Includes boundary validation retry logic.
    *   **Gemini Calls:** Multiple calls to `gemini-2.5-flash-lite`.
    *   **Output:** Consolidated `.json` files in `resources/output/`.

4.  **Enrich Hometowns via Gemini:** `python scripts/update_json_with_gemini.py`
    *   **Purpose:** Queries Gemini to identify official hometowns for athletes where data is missing, standardizing to "City, State."
    *   **Gemini Calls:** Multiple calls to `gemini-2.5-flash-lite`.
    *   **Output:** Updated `.json` files in `resources/output/`.

5.  **Ingest Data into BigQuery:** `python scripts/ingest_hometown_data.py`
    *   **Purpose:** Ingests the enriched JSON files into the `athletes` table.
    *   **Gemini Calls:** None.
    *   **Output:** BigQuery Table: `team_usa_data.athletes`

6.  **Process Geocoding and Create Hubs:** `python scripts/process_geocoding.py`
    *   **Purpose:** Uses Google Maps APIs to add coordinates and elevation. Aggregates data into hubs and synchronizes to the Firestore serving layer.
    *   **Gemini Calls:** None.
    *   **Output:** BigQuery `regional_hubs_summary` and Firestore `hubs` collection.

7.  **Create Sport Summary Table:** `python services/create_sport_summary_table.py`
    *   **Purpose:** Aggregates data from the hub summary to create a per-sport overview.
    *   **Gemini Calls:** None.
    *   **Output:** BigQuery Table: `team_usa_data.sport_summary`

8.  **Generate AI Assets (Images & Narratives):**
    *   `python scripts/generate_sport_images.py`: Generates sport clipart via Imagen 3.0 with sequential retry logic.
    *   `python scripts/generate_hub_images.py`: Generates hub landscapes with linear backoff.
    *   `python scripts/generate_hub_narratives.py`: Generates compliant regional narratives via Gemini 2.5 Pro.
    *   **Output:** GCS Bucket (`-hub-images`), BigQuery (cache), and Firestore (serving).

9.  **Final Optimization & Data Integrity Check:** `python scripts/migrate_images_to_gcs.py`
    *   **Purpose:** Ensures all hub images are optimized WebP files stored in GCS and correctly linked. Acts as a self-healing mechanism.
    *   **Output:** Optimized assets in GCS and verified pointers in BigQuery.

10. **Narrative Formatting & Compliance:** `python scripts/fix_narratives_formatting.py`
    *   **Purpose:** Final sweep to enforce terminology (e.g., LA28) and HTML formatting (e.g., `<strong>` tags) across all narratives.
    *   **Output:** Final sanitized content in BigQuery and Firestore.

*Note: `generate_hometown_registry.py` and `ingest_hometown_registry.py` are alternative ETL paths and not required for the primary application.*

#### 4. Launching the Serving Tier
```bash
python -m uvicorn main:app --reload
```
Navigate to `http://localhost:8000/hubs` to test the interactive map.

#### 5. Verification Checklist
* [ ] **Health:** `GET /health` returns `{"status": "healthy"}`.
* [ ] **Latency:** Clicking a map pin loads hub stats and the Community Cheer Meter from Firestore in <100ms.
* [ ] **AI Integration:** WebP sport icons and regional narratives appear correctly in the side drawer.
